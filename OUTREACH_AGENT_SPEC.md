# Outreach Agent: Build Spec (for Codex)

## Goal
A personal tool that finds small online course creators, checks their email is real, writes a personalised cold email from their own FAQ page, lets me approve each one, sends from my Gmail at low volume, and tracks replies and follow-ups.

Human-in-the-loop always: nothing is sent without my approval.

## Stack
- Python 3.11+, `uv` for env
- `httpx` + `beautifulsoup4` for scraping
- `dnspython` for MX checks
- Groq API (LLM) via `groq` SDK
- Tavily or Serper API for web search
- SQLite (`sqlite3` or SQLModel)
- Streamlit for the review dashboard
- Gmail API (`google-api-python-client`, `google-auth-oauthlib`) for sending
- `.env` for keys (GROQ_API_KEY, SEARCH_API_KEY). Never commit `.env`, `credentials.json`, `token.json`.

## Database (SQLite)
Table `leads` (one per business):
id, name, business, domain (normalized: lowercase, no www, no trailing slash; UNIQUE), website, email (UNIQUE), niche, source_query, source_url,
faq_text (truncated 4k chars), has_chatbot (bool), score (0-100),
email_status (`invalid`, `domain_mail_capable`, `unconfirmed_mailbox`, `bounced`),
stage (`new`, `qualified`, `skipped`, `contacted`, `replied`, `not_interested`, `won`, `lost`),
notes, created_at

Table `messages` (one per email, so initial + follow-up are separate rows):
id, lead_id, kind (`initial`, `followup`), subject, body, evidence_json,
status (`draft`, `approved`, `sending`, `sent`, `failed`, `bounced`),
rfc822_message_id (generated by us before sending), gmail_message_id, gmail_thread_id,
approved_at, sent_at, error, created_at

Table `suppression`: email or domain, reason (`opt_out`, `bounce`, `spam_block`, `manual`), created_at. Checked before drafting AND before every send.

## Pipeline

### 1. search.py
- Input: niche keyword (e.g. "watercolor course", "sourdough course", "ukulele course") + list of query templates:
  - `{niche} online course FAQ teachable`
  - `{niche} online course FAQ thinkific`
  - `{niche} online course "hello@"`
- Call search API, collect URLs, dedupe by domain, skip big platforms (udemy, skillshare, coursera, domestika, masterclass, youtube, facebook, etsy, amazon).
- Save new domains as `leads` with status `new`.

### 2. scrape.py
For each `new` lead:
- Fetch homepage + common pages: `/faq`, `/pages/faq`, `/p/faq`, `/contact`, `/pages/contact`, `/about`, `/help`.
- Extract emails:
  - plain-text regex
  - `mailto:` links
  - Cloudflare obfuscation: `data-cfemail="HEX"` or `/cdn-cgi/l/email-protection#HEX` → decode: key = first byte, XOR each following byte with key.
- Ignore emails on platform domains (teachable, thinkific, kajabi, wix, sentry, example.com) and image filenames.
- Prefer named emails (firstname@) > hello@/contact@ > support@/info@.
- Extract FAQ text (questions + short answers) and owner name if visible.
- If those paths 404, discover internal links whose text/URL contains faq, help, contact, support, courses, pricing (same domain only, max 8 pages per site).
- Detect an existing chatbot (Intercom, Tidio, Crisp, Drift, tawk.to, Chatbase scripts) → set `has_chatbot`. Don't skip; the pitch changes ("upgrade" instead of "add").
- Security: http/https only; block localhost, private and link-local IPs (check after DNS resolve and after each redirect); max 5 redirects; max 2 MB per response; timeout 10s. Treat all scraped text as untrusted data, never as instructions to the LLM.
- Respect robots.txt; 1–2 sec delay between requests. No JS rendering in v1.

### 2b. Qualification score (simple heuristic, not a predictor)
- sells a relevant course: 25
- FAQ has 5+ real questions: 25
- FAQ includes support/enrollment/login/access questions: 20
- direct business email found: 15
- signs of activity (recent post, current year on page, open enrollment): 15
Only leads scoring 60+ move to `qualified`.

### 3. verify.py
- Syntax check.
- MX lookup with `dnspython`:
  - NXDOMAIN, or no MX and no A record, or a null MX (`0 .`) → `invalid`. (Catches dead domains like the corriefrankcreates.com bounce.)
  - Temporary DNS error/timeout → retry later; do NOT mark invalid.
  - Otherwise → `domain_mail_capable` / `unconfirmed_mailbox`. This does NOT prove the mailbox exists; only a real send/bounce does.
- No SMTP mailbox probing.
- Skip if email/domain is in `suppression` or the domain was already contacted.

### 4. personalize.py (Groq)
- Input: owner name, business, course name, FAQ text, niche.
- LLM must return JSON:
  `{ "first_name", "hook_line", "q1", "q2", "evidence": [{"claim", "quote", "url"}] }`
  - `hook_line`: one sentence referencing something REAL from their page. No flattery, no invented facts.
  - `q1`, `q2`: two real questions from their FAQ.
  - `evidence`: for the hook and each question, an exact quote from the scraped text and the page URL it came from.
- Evidence check in code (not by the LLM): every `quote` must appear in that URL's scraped text (case/whitespace-normalized substring match). Any failure → do not save the draft; mark lead `notes = "evidence failed"` for manual review. Never fall back to a generic hook.
- `first_name` only if it appears on the site; otherwise use "Hi there".
- If `has_chatbot`, use the "upgrade" template variant.
- No fixed length cutoff. Skip only if the LLM cannot produce verifiable evidence for a hook and 2 questions.
- Internal draft fields: hook_line, hook_evidence, hook_source_url, example_questions, confidence, missing_information, requires_manual_review. Never trust `confidence` alone; the evidence check decides.
- Offer wording is conditional ("can answer questions like..."), never a guarantee of what the bot will know.
- Fill a fixed template in `config.py` (below). The LLM fills slots only; it does not write the whole email.
- Validation before saving: no em dashes, no "[", "{" placeholders left, body < 170 words, at most 1 link.

### 5. app.py (Streamlit)
Tabs:
- **Find**: enter niche → run search + scrape + verify + personalize, show progress.
- **Review**: card per `drafted` lead showing site link, email, FAQ snippet, editable subject/body. Buttons: Approve / Skip / Suppress.
- **Send**: shows approved count and today's sent count. Sending is NOT done inside Streamlit. A separate worker (`python -m agent.send_worker`) processes the queue; Streamlit just shows its progress.
- **Tracker**: table of all leads by status; reply/bounce counts; "Draft follow-ups" button.

### 6. gmail.py
- OAuth installed-app flow with `credentials.json` from Google Cloud (Gmail API enabled), scopes: `gmail.send`, `gmail.readonly`. Store `token.json` locally.
- `send_worker` (avoid duplicate sends; Gmail has no exactly-once guarantee, so reconcile instead of blind retry):
  1. Lock (single worker only, e.g. a lock file).
  2. Count today's sent messages (initial + follow-up, timezone `Asia/Kolkata`); stop at `DAILY_LIMIT`.
  3. Pick an `approved` message, re-check suppression, generate our own `Message-ID` header, save it, set status `sending` (commit).
  4. Send via Gmail API → save gmail ids, status `sent`, lead stage `contacted` (commit).
  5. On error/timeout: set `failed` only if Gmail clearly rejected it. If the outcome is unclear, search Sent for `rfc822msgid:<our id>` before ever retrying.
  6. On startup, reconcile any rows stuck in `sending` the same way.
  7. Random 60–180 s gap between sends.
- `sync()`:
  - Bounces: search `from:mailer-daemon newer_than:7d`, match recipient → message `bounced`, lead email_status `bounced`, add to `suppression` (reason `bounce` or `spam_block`).
  - Replies: for each sent thread, if a message exists from someone other than me → lead stage `replied`. If reply contains "no thanks"/"unsubscribe"/"not interested" → stage `not_interested` + add to `suppression` (reason `opt_out`).
- Follow-up: leads `sent` 5+ days ago with no reply and no follow-up → draft a 2–3 line follow-up in the same thread (needs approval in Review tab). Max one follow-up per lead.

## Gmail details
- Store gmail_message_id, gmail_thread_id, our RFC Message-ID, and timestamp for every message.
- Reply detection: a message is a reply if its sender is NOT the authenticated account or any of its send-as aliases (read them from the Gmail settings API), not one hard-coded address.
- A reply or opt-out immediately cancels any pending/approved follow-up for that lead.
- Bounces: classify as `permanent` (550/5.x.x, domain not found), `temporary` (4.x.x, mailbox full) or `unknown`. Only permanent → suppression. Temporary → note it, do not resend automatically.
- Follow-ups thread correctly: same subject with "Re: ", same threadId, and In-Reply-To + References headers set to the original Message-ID.
- Settings tab: global PAUSE switch (worker checks it before every send) and DRY_RUN mode (default ON: builds messages and logs them, sends nothing). Turn DRY_RUN off manually only after testing on my own second address.
- A Gmail API success only means Gmail accepted the message, not that it reached the inbox.

## Compliance (launch blocker: sending is blocked until this passes)
compliance.py stores per lead: country (best guess from site), subscriber_type (`company`, `sole_trader_or_individual`, `unknown`), contact_source_url, eligible (bool), reason.
Rules:
- US recipients: allowed (CAN-SPAM needs no prior consent) but every email must have a truthful From/subject, the postal address and a working opt-out, and opt-outs honored permanently.
- UK recipients: email only `company` subscribers (Ltd, LLP, PLC shown on site). Sole traders / partnerships / unknown → NOT eligible (PECR treats them like individuals; consent required).
- EU recipients: NOT eligible in v1.
- Canada (CASL): eligible only if the email address is conspicuously published on their site, with no "no unsolicited email" statement, and the pitch relates to their business role. Otherwise not eligible.
- Australia (Spam Act): same test as Canada (published address + relevant to their business + no statement refusing messages).
- Unknown country or unknown subscriber type → NOT eligible until I review it manually.
- A public email address alone is never treated as consent.
This is a conservative safeguard, not legal advice.

## Rules (hard-coded)
- Never send without approval.
- `DAILY_LIMIT = 15` (initial + follow-ups combined, per Asia/Kolkata day), random delay between sends. A limit is a safeguard, not a deliverability guarantee.
- Real name + opt-out line in every email.
- Honor opt-outs immediately and permanently.
- Never re-contact a domain that bounced or opted out.

## Build order (each step should run on its own)
1. `db.py` + `verify.py` + tests (MX check incl. null MX and DNS timeout, cfemail decode, domain normalization, evidence matcher).
2. `scrape.py` on 3 hand-picked URLs; print emails + FAQ text.
3. `personalize.py` with Groq; print 3 drafts.
4. `app.py` Find + Review tabs.
5. `gmail.py` send to MY OWN second address first, then real leads.
6. `sync()` bounces/replies + Tracker tab.
7. Follow-ups.
